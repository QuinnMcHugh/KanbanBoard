- Learn about the feasibility of Sqlite for this project. Can I use it on Render or would a managed DB hosted elsewhere be preferred? ✅
 - Render can't host the sqlite file but a remote service like Turso can be used for the db while still using Render (both on free tiers) ✅

- Define the requirements for this project ✅
 - This application can be thought of as a cross-company view of all projects, with nothing private among users
 - A UI that allows a user to:
  - sign in / sign out
  - view all the projects
  - open up a project and see the lanes and tasks (with labels if defined)
  - drag and drop tasks in different lanes
  - has pre-defined lanes (this isn't customizable)
  - create new projects
  - create new tasks
  - assign labels to a task
  - create new labels
  - delete labels
  - delete tasks
  - delete projects
  - assign a person to a task
  - edit tasks
  - show the created_at and updated_at times for projects and tasks
 - Entities: users, projects, tasks and labels
  - Users can create projects and can have tasks assigned to them by themselves or others
  - Projects can be created or deleted, and they have tasks associated with them
  - Tasks can be unassigned or assigned to one person. They can have their status changed by anyone
  - Labels can be created or deleted, and they can be associated with tasks (a task can have up to 5 labels)
  - when entities are deleted, their associations to other entities should be cleaned up too ( prevent orphans or bad links)
 - User auth (email and password) - use jwt (research how this works and how it differs from other auth schemes)
  - if someone isn't signed in, then they can't view any data of the site except the landing and login pages
 - Usernames must be unique
 - Have a monorepo structure for the app with server/ and client/ sub-directories
  - The client/ code will be a React SPA
  - The server/ code will facilitate login and implement all API calls
